## 1. 目的と範囲

目的：公式サイト・報道・Xの公式アカウントの新着を見張り、人気が出そうな話題を自動で選び、
その話題の台本と素材（画像・動画・1枚のカード）を、出典つきで用意すること。

範囲に入ること：
1. 新着の収集（RSS・RSSHub・X公式API）
2. 話題の判断（トレンドの分析と、動画にする話題を1つ選ぶ）
3. 台本づくり（Gemini 3.8 Flash。根拠はWeb記事）
4. 素材の取得（根拠の画像・動画を、出典つきで保存）と、Xの投稿のカード作成
5. 一時素材の破棄（実行の最後）

範囲に入らないこと：
- 音声の合成、動画の書き出し、YouTubeへの公開（利用者の指示で対象外）
- 素材や台本の長期保存（保存先は未決定。公開リポジトリのArtifactには入れない方針）

## 2. 全体の流れ（1回の実行の順番）

`.github/workflows/feed-watch.yml` の `watch` ジョブ（ubuntu-latest、上限20分）で、次の順に動きます。

| # | 工程 | 中身 | 費用 |
|---|---|---|---|
| 1 | 依存関係の導入 | `requirements.txt` を入れる。RSSHub（Node）は必要な時だけ入れてキャッシュする | なし |
| 2 | 既読の記録の復元 | `feed-state.json` をActionsのキャッシュから戻す（`feed-state-*`） | なし |
| 3 | 新着の収集 | `tools/feed_watch.py`：RSS（同時に8件）、RSSHub、X公式API（9アカウント） | Xの読み取り（投稿1件0.005ドル） |
| 4 | 判断 | `tools/auto_topic.py --judge openrouter`：Jev（typesafe/jev-router）が、トレンドを最大5つ挙げ、話題を1つ選ぶ | OpenRouter（振り分け先の料金） |
| 5 | 計画 | `tools/video_job.py plan`：依頼の形（request.json）を作る | なし |
| 6 | 撮影の準備 | Chromium を入れる（Gemini の準備で、Web記事の画面を撮るため） | なし |
| 7 | 台本 | `tools/video_job.py prepare --run-paid`：Gemini 3.8 Flash が、根拠の記事から調べて台本を作る | Gemini（調べる・台本の2回） |
| 8 | 素材の取得 | `tools/feed_media.py fetch`：根拠の記事の画像・動画をダウンロード（出典つき） | なし（通信のみ） |
| 9 | フォントの導入 | 日本語のフォント（fonts-noto-cjk）を入れる（カードの文字のため） | なし |
| 10 | カード | `tools/post_card.py`：Xの投稿を1枚のカードにする（Xのページは撮らない） | なし |
| 11 | 成果物の保存 | Artifact `feed-watch-<実行ID>`（14日）。**素材は入れない** | なし |
| 12 | 破棄 | 素材と、台本の下書き（`$RUNNER_TEMP/work`）を消す | なし |
| 13 | 既読の記録の保存 | `feed-state.json` をキャッシュに保存（`if: always()`） | なし |

- 新着が0件の回は、工程 4〜12 を飛ばします（費用はXの読み取りだけになります）。
- 判断で話題が選ばれなかった回も、工程 5〜12 は飛ばします。
- 工程のどれかが失敗すると、後ろの工程は飛ばされます。既読の記録の保存（13）だけは必ず動きます。

手動の実行：`workflow_dispatch` で、いつでも動かせます。
`usage_only` を選ぶと、Xの使用量を表示するだけの実行になります（取得・判断・台本はしません）。

## 4. Xの取り方（公式APIだけを使う）

### 方針
- Xのページを、ログインなしで読んだり、ブラウザで撮ったりはしません。
  Xの決まり（robots.txt）は、検索エンジン以外の自動の読み取りを禁じています。
  実際に、GitHub から `x.com` のページを読むと「403」で拒否されました（2026-11-03）。
  拒否をすり抜ける方法（別サーバー経由など）は、利用者の指示があっても使いません。
- Xの読み取りは、**公式API（api.x.com/2）**だけを使います。鍵は `X_API_BEARER_TOKEN`（GitHubのSecret）です。

### 読み方（`tools/feed_watch.py` の `read_x_api`）
1. ユーザー名からユーザーIDを引く（`/users/by/username/{名前}`）。IDは `feed-state.json` の `x_user_ids` に保存し、2回目以降は引かない。
2. 投稿を読む（`/users/{ID}/tweets`）。
   - `exclude=retweets,replies`：リポストと返信は除く。
   - `referenced_tweets` を見て、**引用**（quoted）・返信（replied_to）・リポスト（retweeted）の投稿は除く（他人の文章を含むため）。
   - `author_id` が監視しているアカウントと違う投稿も除く。
   - `since_id`：前回読んだ一番新しい投稿のIDより新しいものだけを読む（`feed-state.json` の `x_since_id`）。
   - `max_results`：`max_items_per_feed`（15）に合わせる（API上の最小は5）。
3. 画像：`type=photo` の `url` を使う。
4. 動画：`video`／`animated_gif` は、`variants` のうち `video/mp4` で最も `bit_rate` が高いものを使う。代表画像（`preview_image_url`）も保存しておく（カードに使う）。

- 画像・動画の取得（配信先からの直接取得）は、APIの課金の対象外と見込んでいます。ただし、**これは私が料金表を読んで判断したもので、請求で確かめたわけではありません。**

## 7. 画像・動画・カード（出典つき）

### 取得（`tools/feed_media.py fetch`）
- 対象：選ばれた話題の根拠（`urls` と `x_urls`）の記事に付いている画像・動画だけ。
- 件数：1話題で最大8件。候補は最大16件まで見る。
- 大きさ：画像は1件30MBまで、動画は1件100MBまで、合計150MBまで。
- 種類：`image/*` と `video/*` のみ（content-type で確かめる）。https のみ。
- 並列：6件まで同時に取る（速さのため）。
- 出典：**すべてのファイルに「出典: 媒体名（記事のURL）」を付け、取得の記録（`manifest.json`）に入れる。**
  - RSSの記事：媒体名は、フィードのタイトル（取れなければフィードの番号）。
  - Xの投稿：「@アカウント名（X公式）」。
- 記録：各ファイルの出典URL、取得元URL、大きさ、SHA-256、取得時刻、出典の文。

### カード（`tools/post_card.py`）
- 対象：根拠のXの投稿のうち先頭1件（`x_urls[0]`）。
- 作り方：公式APIで取った本文・画像（動画なら代表画像）を、HTMLの1枚の画面にして、Chromiumで撮る。
  **Xのページは撮らない。** カードは「自分の画面」です。
- 本文は、HTMLとしてではなく文字として表示する（`<script>` などは無効化される。テストあり）。
- 出典：カードの下に「出典: @アカウント名（X公式）（投稿のURL）」を表示する。
- 記録：`manifest.json` に `kind: card` として入れる。
- 文字：日本語のフォント（fonts-noto-cjk）を、GitHub の実行で入れてから作る。

### 破棄
- 素材（画像・動画・カード・撮った画面・台本の下書き）は、実行の最後（`if: always()`）に消す。
- Artifactには入れない。このリポジトリは公開で、Artifactは誰でも取れてしまうため。
- 動画制作の後の破棄は、`tools/feed_media.py discard --out <フォルダ>` を使う。破棄の記録（SHA-256の一覧）を、フォルダの横に残す。
- ※動画制作の工程は、この構築の範囲外のため、いまは実行の最後に消す形になっています。

### 権利について（未決定）
- Xの画像・動画は、他人の著作物です。出典は付けますが、**動画制作でどう使うかの決まりは、まだありません**。
  制作の前に、`quality_gates.image_allowed` に、Xの画像の扱いを加える必要があります（利用者の判断が要ります）。
- 利用者の決まり（2026-11-03）：他人の動画の切り抜きは、出典を出せば使える。再生できなかった画面は使わない。

  - 公的でないサイトの関連画像は、台本の入力から外す（既存のルール）。
- 規約とアクセス：Xのページは読まない・撮らない（robots.txtと規約による）。拒否を回り道で回避しない。
- 無料と有料：無料モデルも有料モデルも、切り替えは自動でしない。失敗したら、そのまま止まる。
- 費用の上限：OpenRouter の鍵に上限（$4）を設定した。Xの読み取りは、新しい投稿だけにして重複を減らした。
