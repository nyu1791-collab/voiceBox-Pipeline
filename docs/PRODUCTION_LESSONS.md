# 制作の反省と背景（参考）

**`docs/RULES.md` が常に優先する。本書は背景資料で、追加の必読ではない。** 新しい検査・査読・確認待ちを増やす根拠にもしない。2026-09〜10 の旧制作環境の記録を要約し、2026-11-01 に本リポジトリのコードと照合した。`[差異]` は当時と現行が違う箇所。`旧R` は旧規則の番号で、現行の規則番号ではない。

## 1. 描画と符号化

- **分割描画はしない（旧R2）**：8 区間に分けて描くと、一本描きと比べて区間 2〜7 に合計 313 フレームの不一致が出た。原因は区間の先頭の画面状態が一本描きと異なること。一本描きと中間ファイルなしの直接符号化を採用し、60 秒の比較で映像の MD5 が旧経路と一致した。現行の `pipeline.py` も全編を一本で直接符号化し、音声結合では映像をコピーする。`[差異]` 描画器には区間描画の分岐が残るが、標準経路では使わない。
- **「1 スレッド固定」の記述は古い（旧R8）**：x264 を 8 スレッドにしても、同じ設定の 2 回で 600 フレームすべて一致した。1 スレッドとは 325 フレーム違う。8 スレッドで映像が毎回変わるという当初の判断は誤りで、速さの差も約 9% だった。スレッド数を変えると映像は変わるので、比較は設定を揃える（旧R20）。
  - `[差異]` 現行の `pipeline.py` は 4 スレッドを指定する。4 の再現性は未計測。計測時は 720p・preset fast で、現行の 360p・veryfast・24fps とも条件が違う。
  - `[差異]` 描画器の既定値（8）の横には「1 で再現する」という古いコメントが残る。
  - VOICEVOX の「エンジンごとに 1 スレッド」は合成の現行規則で、上の話とは別。
- **実際に使う経路で確かめる（旧R38）**：字幕の強調を使われない旧分岐に書き、全編で出ていなかった事故が起点。設定や関数があることは、効いている証拠にならない。
  - `[差異]` 現行の例：プロファイルに `chapter_card` の値はあるが、`pipeline.py` が作る `presentation` に `chapter_cards` がなく、標準経路では章カードが出ない。
- **口と画面状態は全編の時刻で計算する（旧R6）**：区間の先頭からの番号に依存すると位相がずれる。
- **重い原因は計測で探す**：描画が約 4 分かかった主因は、図解の文字を毎フレーム 4 倍で描いて縮める処理だった（20 秒の区間で 31.15 秒対 8.72 秒）。字幕の折り返しの再利用（20 秒の区間で 27.8→15.5 秒）と字体の共通化（60 秒の区間で 27.4→22.7 秒）は、MD5 が一致したまま短縮できた。
- **描画時間と全体の時間を混同しない**：描画 66 秒を、描画・QA・連絡シートの 88.7 秒や、全体の約 40 分と取り違えた例がある。工程タイマーは計測手段で、高速化そのものではない。

## 2. 台本とスライド

- **話し始めで切り替える（21-3）**：スライドは、その内容を最初に話す台詞の開始と同時に替える。話し終えてから替えず、話題が変わった台詞に前のスライドを残さない。現行は台詞ごとの `visual` で、台詞の開始時に切り替わる。
  - `[差異]` `visual` を省略した台詞は直前の資料ではなく先頭の資料になる。意図した資料は台詞ごとに書く。
- **水増しせず、問い→結論→上澄み→次へ（21-4）**：要点を平易に一度まとめて次へ移る。章末に次への一文を置き、同じ主張を章をまたいで繰り返さない。まとめは既出の要点を一回だけ整理する。
  - `[差異]` 当時の「8 分以上」「本編 6 章」は現行規則ではない。尺は目安（RULES）。
- **冒頭と構成（旧§6）**：前置きで始めず、結論・問い・得する点のどれかから入る。中心の問いは 1 つ。専門語は最初に一度だけ身近な例で言い換える。「問い→要点 3〜5 個→何が変わるか→身近な例→限界・未確定点→一文まとめ」も使いやすい型。秒数の基準（3・15・30 秒）は当時の目標で、現行の必須値ではない。
- **枠に文字を重ねない（旧R69）**：画像・表・グラフの枠には画像だけを載せる。現行も `MOTION_TEXT_IN_VISUAL_SLOT = False`。中央パネルにナレーションを丸写ししない（旧R60）。

## 3. 参考動画の計測（22-11）

解説動画 1 本（726 秒）を計測した記録で、規則ではない。

- 図の領域は 93% の時間で静止。動くのは場面の入りの約 1.4〜1.7 秒と章カード。小さな局所変化は数秒おきにあるが、画面全体は動かない。
- 章カードは 8 回、各 約 2.1 秒、話し声なし（−46 dBFS）。
- 字幕は暗い半透明の板に白文字。ただし当時も採用しなかった。
- 短い録画の後半は一時停止中だったので、静止の根拠に使っていない。

`[差異]` 図の入りは、当時の 1.5 秒に対し現行プロファイルは 0.45 秒（`visual_entry_seconds`。値がない場合の描画器の既定は 1.5）。10 秒ごと・2.5 秒・2% の寄せは現行と一致。現行の字幕は淡い板に濃い文字。

## 4. 字幕・読み・表情

- **読みと字幕は別データ**：字幕は `OpenAI`、読みは「オープンエーアイ」とし、カタカナを字幕へ自動コピーしない。`[差異]` 現行のフィールドは `text`（字幕）と `speech_text`（読み。任意）で、当時の `voice_text` / `caption_text` と形が違う。
- **字幕は意味で切る**：文字数上限は安全上の上限で、埋める目標ではない。固有名詞、略語、数値と単位を分断しない。実際に「攻／撃」「書／かれ」で割れた例がある。現行は BudouX と禁則で折り返す。
- **口は位置まで見る**：動いていても顔からずれれば失敗。同時に有効な口は 1 キャラ 1 枚で、元の口に別の口を描き足さない（現行も同じ）。素材や寸法を変えた時だけ見直せばよい。
- **弾みだけで動きを済ませない**：意味の切れ目で表情・視線・ポーズを変える。表情は本文の一致辞書で引かず、台詞に持たせる。辞書方式では文言修正で静かに通常顔へ戻る（現行は台詞ごとの `emotion`）。
- **変えていないものは作り直さない**：字幕色だけなら音声を、表情素材だけなら音声と出典素材を維持する。

`[差異]` 当時の字幕色（暗い板に淡いミント・ローズ）と、外部編集ソフトを第一選択とする方針は現行と違う。現行は RULES とプロファイルに従う。

## 5. 撮影の詰まり（2026-10-19 の分析）

遅れの最大要因は描画でなく撮影だった。審査は合計約 13 秒で、撮影は 309 秒かかった回がある。

| # | 起きたこと | 教訓と現行の状態 |
|---|---|---|
| C1 | 外部サイトの HTTP 429。約 9 分待機し、5 分の冷却は効かなかった | 429 だけ上限付きで再試行する（現行 60 秒・180 秒、`Retry-After` は 300 秒まで）。原因の特定と頻度の低減は未了 |
| C2 | 最初の一致が折りたたまれた目次の隠れ要素 | 可視で、目次や infobox の外の一致を選ぶ（現行 `pick_block`） |
| C3 | 別の対象が同じ段落を指した | 使用済みの段落を避ける（現行 `pick_block`）。段落の意味が場面に合うかは機械では分からない |
| C4 | 撮影語を手で変え、受領記録の SHA と不一致で停止 | 生成物を手で変えず、元の入力を直して再生成する |
| C14 | 撮影コードの小さな修正で受領記録が無効になり、撮り直しで約 5 分 | 再利用の判定は内容（台本・素材表・撮影語・出典）だけにする。現行の `plan_inputs` も同じ |

音声キャッシュも同じ考え方で、コード全体の SHA ではなく `SYNTH_REVISION` を鍵に使う（RULES）。

その他の失敗：

- C7・C8：場所や HTTP 状態を先に確かめず、別の原因を調べた。
- C9：試験の作り方自体の誤りを 3 回直した。
- C10・C11：待機の方法や `&&` と `&` の優先順位で、確認をやり直した。
- C12：大きな出力を表示してトークンを浪費した。件数とハッシュで見る。
- C13：削除コマンドは対象を確かめてから実行する。

## 6. 起きやすい失敗

| 失敗 | 教訓 |
|---|---|
| `eval "$(cmd)" \|\| exit 1` が失敗を握りつぶし、別の原因を表示した | 代入してから判定する |
| 検査プログラムが FAIL でも終了コード 0 で、呼び出し側は終了コードしか見ていなかった | FAIL と未実施を成功に数えない |
| 描画前に全体 OK を書き、後段の失敗が隠れた | 工程の状態を分ける。保存成功と品質完成は別 |
| 待ちの判定が前の実行の行に一致した | 今回の実行の行だけを見る |
| `pkill -f` が自分のシェルを止めた | PID で止める |
| 本文の「判定: 合格」を拾って合格扱いにした | 判定は決まった位置だけを見る |
| `round` と `ceil` でフレーム数が 1 枚ずれた | 計算式を一か所に揃える |
| 台本変更後に古い WAV が残った | 入力のハッシュで由来を見る |
| 相対パスの取り違えで描画が失敗した | 版のフォルダから素材を解決できるようにする |
| `.gitignore` の広い除外が記録まで隠した | 重い中間物だけを除外する |
| 合成後にしか分からない検査を合成前に要求する案が出た | 実音声が要るものは合成後に回す |
| 似た画像を知覚ハッシュで自動失敗にする案が出た | 同じページの別段落は正しい根拠になり得る |
| 数値の音量検査を耳の確認の代わりにした | 実施した範囲を書き、未実施を成功と呼ばない |
