# 噂の紹介動画の作り方（手順書）

対象: 噂・未確認の情報を「噂」「非公式」と明記して紹介する動画（本編 720p と縦型ショート）。
公開は、利用者が決めるまでしない。公開するときは、資料の利用の確認を先に行う。

## 方針（2026-11-03 の利用者の指示）
- 出典の確認は、求めない（ただし、噂・個人の投稿だと必ず明記する）。
- 公式の情報と、個人の投稿は、台詞の中で分けて話す。
- 投稿者本人の補足（冗談、注意書き）は、必ず台詞とカードの両方に入れる。
- ログイン、Cookie、APIキーは使わない。アクセスが拒否されたページは、回避せず「取れなかった」と記録する。

## 手順
1. **話題を決める**: 噂の内容と、そのきっかけの投稿を一つずつ書く。
2. **資料を集める**
   - 記事: GitHub Actions の「Research and JSON Project」（Gemini の検索で資料と台本の下書きを作る）。
   - 投稿者の最新投稿: `x-public-profile.ps1`（ユーザー名を指定。最新5件）。
   - 投稿の画面: `tools/rumor_video/capture_post.ps1`（ログインなしのブラウザで開いて、本文を切り抜く。取得の記録は `capture-log.json`）。
3. **台本を作る**
   - 1行は、46字以内（字幕の枠に収めるため）。長い台詞は `tools/rumor_video/split_captions.py` で分ける。
   - 公式の情報は「公式の投稿で確認できたこと」、噂は「〜と言われています／投稿されています」と書く。
   - 投稿者の補足や、注意書きを必ず入れる。
4. **材料のフォルダを作る**: `media/projects/<話題>-<日付>/`
   - `project.json`（台本）、`materials/`（画面の切り抜き）、`README.md`（状態と確認が必要な箇所）。
5. **本編を描画する（720p）**
   - `python tools/rumor_video/render_project.py --project-dir <材料> --out-dir <保存先>`
   - Colab の GPU（L4）を使う。描画が終わると、ランタイムは自動で止まる。
   - 接続が切れたら、最大3回まで、新しいランタイムでやり直す。
6. **縦型ショートを作る**
   - `python tools/rumor_video/make_short.py --video <本編> --out <ショート> --font <フォント> --head <見出し.txt> --points <要点.txt>`
   - 本編の冒頭58秒。見出し、映像、要点（非公式の表示つき）の順。
7. **確認する**: 字幕が切れていないか、資料の文字が読めるか、噂の表示が入っているかを、画面で確かめる。
8. **保存する**: `media/exports/<話題>-<日付>/`（`video-720p.mp4`、`short-1080x1920.mp4`、`README.md`）。

## 既知の注意点
- 投稿者本人の補足を、省かない。省いた版は誤解を生む（2026-11-03 の訂正で確認）。
- 資料の画面は、拡大した文字が読める大きさで入れる。全体を縮めた画像は、読めない（2026-11-03 の指摘）。
- 字幕の1行が長いと、枠の下で切れる。46字以内に分ける。
- Colab との接続は、最初の命令で切れることがある。新しいランタイムでやり直す。
- 第三者の投稿・記事の画面は、公開の前に利用の確認が必要。

## 残っている課題
- 資料の撮影（投稿の画面）は、今は手作業の補助（PowerShell）。ブラウザの画面の大きさが変わると、切り抜き位置の調整が必要。
- 字幕の分割は、読点の位置で機械的に分けている。話し方を、自然にするための調整は、人が見て行う。
- 公開の仕組み（YouTube への投稿）は、非公開のアップロードまで。公開は人が行う。
